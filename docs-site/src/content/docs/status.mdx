terragucci is being built. The rest of this site describes it finished, so this page is the one to read before relying on a feature. It is authoritative over every other page and the README.

## What you can run today

| Piece | What works |
|---|---|
| The tutorial's example | `just example up` boots 15 roots on a local Forgejo and applies them to floci, with the scenarios ready to open as pull requests |
| The check stage | format and validate on every pull request, failing by file name |
| `npx terragucci init` | finds a repo's roots, binary and forge, and writes its pipeline for GitHub, GitLab or Forgejo; the pipeline checks every root and applies them in dependency order on the main branch |
| CI images | one per toolchain (OpenTofu, Terraform, Terragrunt), built and checked on amd64 and arm64; not yet published, so `init` pins them by tag until they are |
| `terragucci stage tf-plan` | plans every root and writes the plan report: JSON, HTML, the pull-request note and GitLab's counts, with each root's full plan beside it, sensitive values redacted; with `reports.bucket`, copies it to the bucket and updates the index. The generated pipeline's plan job runs it on every pull request, posts its note and keeps it as the job's artifact |
| Traces and metrics | with an OTLP endpoint set, `tf-plan` sends one trace per run, with a span per wave, root and binary run, and OpenTofu's own spans inside it; and its metrics, read from the report |
| `terragucci.yml` and `terragucci reconcile` | one config for one repo or many; from a control repo, a pull request in each project that changes |
| The local validation stack | Forgejo with its runner and floci; GitHub, GitLab and fountain setups are declared but not yet checked |

## What the checks show

Each feature on this site has one check, run against the [tutorial's example](/terragucci/tutorial/) on a local Forgejo. A check that passes has also been broken on purpose, and it failed then.
