## Change one root

Orders in dev should keep unpicked jobs for seven days instead of four: one line in `envs/dev/orders/main.tf`. One command makes the branch and opens the pull request:

<Captured step="first-pr" />

The push and the pull request each start a run. The pull request's run posts the plan note and the push's run is the check; take the run numbers from the output.

Open the pull request link in Forgejo:

<Shot step="first-pr" view="files" alt="The pull request's files tab, adding job_retention_seconds = 604800 to dev orders" />

`tf-check` runs on the branch push, and on a pull request only from a fork: a format check, then `validate` for every root. Look at the push's run, the second link printed. Both steps pass. The plan note is a comment in the conversation:

<Shot step="first-pr" view="pull" alt="The pull request in Forgejo with its check passing and its plan note for the one root" />

## Break the formatting

Now add a badly formatted file:

```hcl
locals {
    team   = "orders"
  owner = "shop"
}
```

The scenario opens it as a second pull request. The check fails, and `just example logs` prints the file and the change `tofu fmt` would make.

<Captured step="check" />

In Forgejo the failed step is "Format check and validate, every root":

<Shot step="check" view="log" alt="The failed check job in Forgejo, its format step open on the diff tofu fmt -check printed for envs/dev/orders/locals.tf" />

Run `tofu fmt -recursive` in your own repo and the check goes green again.

## What you saw

Every push runs the check stage on every root. It needs no cloud credentials, because it never plans.
