:::note[Where the example stands]
Booted with `just example up`. `just example reset` gets you back to that from any step.
:::

The apply is one job per wave, canary first.

| Wave | Roots |
|---|---|
| 1 | the dev platform root |
| 2 | the four dev services |
| 3 | the staging and prod platform roots |
| 4 | their eight services |

The gate is `on-destroy`, the default. A wave waits only when its plans destroy or replace something. Make one do that:

<Captured step="wave-waiting" cmd="just example change destroy" optional />

That pull request drops the records table of staging email. Its note names the destroy at the top:

<Shot step="wave-waiting" view="pull" alt="The destroy pull request's plan note, with the records table of staging email named as a destroy above everything else" optional />

Merge it with `just example merge destroy`, or in Forgejo signed in with the account `just example up` printed. The first terminal merge also generates a key and commits it to `.chant/allowed_signers` on main, the file that says who may approve. Wave 4 plans the destroy and stops: its job exits with code 3 and prints the approve command:

<Captured step="wave-waiting" cmd="just example merge destroy" optional />

<Shot step="wave-waiting" view="log" alt="Wave 4's apply job in Forgejo, stopped with exit code 3 and printing chant approve tf-apply wave-4 with the plan's digest" optional />

Read the wave's plans in the report first. The [`chant approve`](/terragucci/concepts/glossary/#chant) command carries the digest the wave planned, so the approval covers those plans and no others. In your own repo you run it with your own key, listed in `.chant/allowed_signers`; [Approve a waiting wave](/terragucci/guides/approve-a-wave/) sets that up.

In the example, use the generated key:

```bash
just example approve
```

It runs `chant approve tf-apply wave-4` with that key. The wave counts the approval only when the key is listed in `.chant/allowed_signers` on the default branch as it was before the merge being applied.

Run the wave's job again and wave 4 applies. A plan that changes afterwards is not covered, as the next page shows.

To make every wave wait, set `gate: always` in `terragucci.yml`.
