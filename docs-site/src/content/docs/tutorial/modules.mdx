:::note[Where the example stands]
Booted with `just example up`. `just example reset` gets you back to that from any step, and removes the release tags this page makes.
:::

When roots pin a published version, a module change reaches no root until a pin moves. `tf-publish` publishes a module version, and `tf-rollout` moves the pins one wave at a time, each wave its own pull request.

The scenario first tags `modules/service` at `1.0.0` with `tf-publish` and pins the twelve service roots to that tag on main. The changed module is published as `1.1.0`, and the rollout runs:

```bash
just example change pin
```

The last command it ran is `terragucci rollout modules/service --mode apply`. Here `apply` means opening the pull request; no `terraform apply` runs until it merges. It takes the newest version, `1.1.0`, and opens the canary wave, the dev services, moving each `ref` from `modules/service/v1.0.0` to `modules/service/v1.1.0`.

Merge it, and let the apply on the merge commit finish. Then open the next wave's pull request:

```bash
just example rollout
```

It runs the same `terragucci rollout` command. Each run takes at most one step, so the next wave opens only once the last has applied. [Publish your modules](/terragucci/guides/publish-modules/) adds the publish job, and [Roll out a new module version](/terragucci/guides/roll-out-a-module-version/) has every step.
