:::note[Where the example stands]
Booted with `just example up`. `just example reset` gets you back to that from any step.
:::

Every stage can send traces and metrics to an OpenTelemetry collector. `dashboards: true` makes `init` write the Grafana dashboards and alert rules too. This page sends three runs of the example to Grafana:

```bash
just see-runs
```

<Captured step="see-runs" />

It runs three stages on a copy of the example with `OTEL_EXPORTER_OTLP_ENDPOINT` set:

| Stage | Run | Result |
|---|---|---|
| `tf-plan` | the module-bump change | success |
| `tf-drift` | after deleting staging orders' jobs queue from [floci](/terragucci/concepts/glossary/#floci), as on the [Drift](/terragucci/tutorial/drift/) page | success |
| `tf-apply` | the waves, with the gate set to `always` | wave 1 has nothing to change and passes; wave 2 waits for an approval |

The ledger goes to a scratch repo, so the Forgejo example stays as it was.

Open Grafana at [localhost:3310](http://localhost:3310) and look in the `terragucci` folder. The pictures below show the last hour.

## Pipeline health

<Shot step="see-runs" view="pipeline" alt="The Pipeline health dashboard: runs per hour, errors and duration for the tf-plan, tf-drift and tf-apply stages of the example" />

Each stage run is one span, counted by stage and outcome. The plan and drift run are successes, and the waves are `nothing` and `waiting`, not errors.

## Rollouts and waves

<Shot step="see-runs" view="waves" alt="The Rollouts and waves dashboard, with wave 2 of the example waiting for its approval" />

No wave was refused or failed. A wave waiting longer than `wave_wait` (four hours by default) fires `TerragucciWaveWaiting`.

## Drift

<Shot step="see-runs" view="drift" alt="The Drift dashboard: the example's drifted roots, and how long its drift has stood" />

The drift run finds the deleted queue in staging orders, and floci's missing tags on every root. Once the drift's age passes `drift_age` (a day), `TerragucciDriftOld` fires.

## Runs

<Shot step="see-runs" view="runs" alt="The Runs dashboard: the slowest roots of the plan, the stage durations, and the three runs' traces from Tempo" />

[Traces and metrics](/terragucci/reference/observability/#dashboards-and-alerts) lists every dashboard, the alert rules and the collector settings.

## In your own repo

Add the key and run `init`:

```yaml
dashboards: true
env:
  OTEL_EXPORTER_OTLP_ENDPOINT: https://otel-collector.example.com:4318
```

`init` writes the dashboards under `observability/terragucci/`. Point Grafana and Prometheus at that directory, and give your collector the `spanmetrics` connector.
