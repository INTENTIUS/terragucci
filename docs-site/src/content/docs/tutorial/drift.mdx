:::note[Where the example stands]
Booted with `just example up`. `just example reset` gets you back to that from any step.
:::

Someone deletes a queue in the console. This scenario does the same through the API.

<Captured step="drift" optional />

The `drift` job runs at six every morning, or by hand from the Actions tab. It plans every root with `-refresh-only`, which compares state with what exists in [floci](/terragucci/concepts/glossary/#floci) and ignores the code. The report lists the deleted queue under deletes, in `envs/staging/orders` as `module.service.aws_sqs_queue.jobs`.

:::note
floci does not keep tags, so tags show as drifted on every root. On AWS they would not. Look for the entry marked deleted outside Terraform.
:::

The job opens one issue, `terragucci: drift found`. It names `envs/staging/orders` and the queue `shop-staging-orders-jobs`. A second run updates it.

<Shot step="drift" view="issue" alt="The drift issue in Forgejo, naming envs/staging/orders and its deleted queue shop-staging-orders-jobs" optional />

A change waiting on main is not drift: a refresh-only plan never reads the code.

Applying the code recreates the queue, which `just example reset` does. On AWS the next drift run closes the issue; on floci the tag entries keep it open.
