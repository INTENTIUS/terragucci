:::note[Where the example stands]
Booted with `just example up`. `just example reset` gets you back to that from any step.
:::

Someone deletes a queue in the console.

<Steps>

1. The scenario deletes it through the API.

   <Captured step="drift" optional />

2. Run the `drift` job by hand from the Actions tab, or wait for six in the morning. Its `-refresh-only` plan of every root compares state with what exists in [floci](/terragucci/concepts/glossary/#floci) and never reads the code, so a change waiting on main is not drift. The report lists the deleted queue under deletes, in `envs/staging/orders` as `module.service.aws_sqs_queue.jobs`.

   :::note
   floci does not keep tags, so unlike AWS it shows tags as drifted on every root. Look for the entry marked deleted outside Terraform.
   :::

3. Open the issue the job opened, `terragucci: drift found`. It names `envs/staging/orders` and the queue `shop-staging-orders-jobs`. A second run updates it.

   <Shot step="drift" view="issue" alt="The drift issue in Forgejo, naming envs/staging/orders and its deleted queue shop-staging-orders-jobs" optional />

</Steps>

Applying the code recreates the queue, which `just example reset` does. The next drift run then closes the issue on AWS; on floci the tag entries keep it open.
