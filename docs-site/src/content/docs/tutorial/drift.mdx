:::note[Where the example stands]
Booted with `just example up`. `just example reset` gets you back to that from any step.
:::

Someone deletes a queue in the console. This scenario does the same through the API.

```bash
just example change drift
```

The example's `terragucci.yml` schedules drift for six every morning. The pipeline's `drift` job runs then, and you can start it by hand from the Actions tab. It plans every root with `-refresh-only`: each root's state is compared with what exists in floci, and the code is ignored. Staging orders reports its queue as deleted outside Terraform. No other root is listed, so the report has one drifted root.

The job opens one issue, `terragucci: drift found`. It names `envs/staging/orders` and the queue `shop-staging-orders-jobs`. Run the job again and the same issue is updated, not duplicated.

A change waiting on main is not drift. Merge a pull request from the earlier steps without applying it, and the next drift run still reports only the queue, because a refresh-only plan never reads the code.

Correct the drift the way you correct anything else. Applying the code recreates the queue, which `just example reset` does. The next drift run finds nothing and closes the issue.
