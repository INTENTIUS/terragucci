terragucci 0.4.3 is on npm as `@intentius/terragucci@0.4.3`, and its [GitHub release](https://github.com/INTENTIUS/terragucci/releases/tag/v0.4.3) lists every change.

| To upgrade | Run |
|---|---|
| Each repo | `npx @intentius/terragucci@0.4.3 init`, then merge the pipeline it writes |

## Approvals and chat

| What | Where |
|---|---|
| `terragucci approve` pushes an approval to [`chant/lifecycle`](/terragucci/concepts/glossary/#chantlifecycle) with your token, and a scheduled resume job starts the wave it approves | [Approve with chant](/terragucci/guides/approve-a-wave/#approve-with-chant) |
| `terragucci approve --plan <digest>` approves only that plan digest | [Approve with chant](/terragucci/guides/approve-a-wave/#approve-with-chant) |
| Under `approval: pr-review`, a waiting wave's chat message links the pull request's review | [Approve from the message](/terragucci/guides/notify-a-chat-channel/#approve-from-the-message-by-review) |
| `notify` posts a signed, versioned JSON event to a webhook of your own | [Send events to your own webhook](/terragucci/guides/notify-a-chat-channel/#send-events-to-your-own-webhook) |
| An approval's audit entry records who relayed it | [Audit trail](/terragucci/reference/audit-trail/) |

## Modules

| What | Where |
|---|---|
| `modules.attest: true` signs each module release with cosign, with provenance and an SPDX SBOM, and records it in the release ledger | [Attest each release](/terragucci/guides/publish-modules/#attest-each-release) |
| `modules.require: attested` makes `tf-check` and `tf-plan` refuse a root that pins an unattested release | [Require attested releases](/terragucci/guides/publish-modules/#require-attested-releases) |
| A scheduled job continues every rollout in flight | [Roll out a new module version](/terragucci/guides/roll-out-a-module-version/) |

## The estate page

| What | Where |
|---|---|
| The resources each root holds, by address, type and provider, never values | [See every project](/terragucci/guides/see-every-project/#the-resources) |
| Each resource's change history, with who approved each apply | [See every project](/terragucci/guides/see-every-project/#change-history) |
| JSON Schemas for `index.json`, `estate.json` and audit lines, and the bucket layout on one page | [Reports bucket](/terragucci/reference/reports-bucket/) |

## Security and control repos

| What | Where |
|---|---|
| No forge token where a pull request's code runs: separate note jobs, a `fmt` job and checkouts without credentials | [Threat model](/terragucci/reference/threat-model/) |
| A control repo's defaults reach each project: `reconcile` writes every key the jobs read into its `terragucci.yml` | [Govern many repos](/terragucci/guides/govern-many-repos/) |
| An estate of 10,069 resources in 1,361 roots, planned and applied through the generated pipeline | [Scale](/terragucci/reference/scale/) |

## Fixes

| What | Where |
|---|---|
| The check step runs when its shell cannot restart itself | [Pipeline](/terragucci/reference/pipeline/) |
| Rollouts read Forgejo's 404 on a just-pushed repo's pull requests as none open | [Roll out a new module version](/terragucci/guides/roll-out-a-module-version/) |
| On GitLab, an apply wave under policy pushes with the project token, so a denial under `gate: never` is recorded for an override | [Overriding a denial](/terragucci/reference/policy/#overriding-a-denial) |
