Before a release, every pipeline terragucci generates runs against an AWS emulator. Each feature's check must pass, and also fail when broken on purpose.

| Forge | What runs |
|---|---|
| Forgejo | a Forgejo server and its runner |
| GitHub | the generated workflow, run by `act` against a mock GitHub API |
| GitLab | GitLab CE and its runner |

Forgejo, GitHub and the AWS emulator are checked on every pull request to terragucci. GitLab is checked every night, because its server is heavy.

## The claims

Each claim also runs with its property broken, and must then fail. `reconcile` follows a control repo's pull request through check, merge and apply. `tg-` claims run a two-unit Terragrunt repo and `cdf-` claims a [choudoufu](/terragucci/concepts/glossary/#choudoufu) estate, each in its pinned CI image.

## The example's checks

Each feature has one check, run against the [tutorial's example](/terragucci/tutorial/) on a local Forgejo. A check that passes has also been broken on purpose, and it failed then.

The same setup runs on your laptop. [The tutorial](/terragucci/tutorial/) boots it with one command and walks through each feature.

## Running it yourself

```bash
just stack-up forgejo
just smoke
just stack-down
```

`just validate <forge> <claim>` runs one claim and `just validate-forge <forge>` all of a forge's, plain and broken. `just validation-record` rewrites the table above after a full run.

`just smoke` prints one line per check. `BREAK=1 just smoke <check>` breaks the property on purpose, and the line must then say `caught`.
