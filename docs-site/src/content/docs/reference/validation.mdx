Every pipeline feature has a check that runs on a local Forgejo against an AWS emulator. The per-forge claims below list what is also proven on GitHub, github.com and GitLab. A local check must pass, and also fail when broken on purpose.

| Forge | What runs |
|---|---|
| Forgejo | a Forgejo server and its runner |
| GitHub | the generated workflow, run by `act` against a mock GitHub API |
| github.com | the published release's generated workflow on GitHub-hosted runners, in a public plan-only repo, each night |
| GitLab | GitLab CE and its runner |

## The per-forge claims

These are the features proven on each forge. Each claim also runs with its property broken, and must then fail. `reconcile` follows a control repo's pull request through check, merge and apply. `tg-` claims run a two-unit Terragrunt repo and `cdf-` claims a [choudoufu](/terragucci/concepts/glossary/#choudoufu) estate, each in its pinned CI image.

The github.com claims run the newest published release against real GitHub: its pull request events and statuses, comments and reviews, and OIDC tokens. Every resource there is a `terraform_data`, so nothing needs a cloud account. That has these limits:

| Limit | What runs instead |
|---|---|
| no cloud role | `oidc` checks each job's token against GitHub's published keys, its repo, run, audience and role, and trades it with nothing; the trade with STS is proven on Forgejo |
| no bucket | report upload credentials are proven on Forgejo, against the AWS emulator; the estate page's scheduled job does not run here |
| one GitHub account | the refusals of a commenter with no write access and of a pull request from a fork are proven on Forgejo; the apply-before-merge pull requests are opened by a workflow, so the account that runs the claims may approve them |
| no model key | the agent comment and the refused-wave job run a stand-in agent that makes one edit or prints the summary input |
| no broken run | these claims are not broken on purpose, so they read "passes" |

## The example's checks

Every pipeline feature has a check here, run against the [tutorial's example](/terragucci/tutorial/) on a local Forgejo. A check that passes has also been broken on purpose, and it failed then. The GitLab column lists the checks that also run on a local GitLab CE and its runner, each in a small repo with the pipeline `terragucci init` writes for GitLab.

The same setup runs on your laptop. [The tutorial](/terragucci/tutorial/) boots it with one command and walks through each feature.
