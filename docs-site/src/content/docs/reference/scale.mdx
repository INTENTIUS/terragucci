The scale bench runs the pipeline `terragucci reconcile` writes over one estate at five sizes, the largest 10,069 resources in 1,361 roots across 12 repos. It runs on a local Forgejo against an AWS emulator.

## The runs

<ScaleRuns />

| Column | What it counts |
|---|---|
| Create | from merging the pipeline pull requests to the end of the last run: every root planned by its waves and applied from nothing |
| Plan | from pushing a change that every root takes to the end of the last pull request run: every root planned, one plan note per repo |
| Change | from merging those pull requests to the end of the last run: every root planned again and the change applied |
| Runner minutes | the time of every job in every repo, the check jobs included, for the whole run |
| Largest plan note | the largest note one pull request got, in bytes |
| Largest report | the largest `report.json` one stage wrote to the reports bucket |
| Run | the terragucci build, the day, the machine and how many jobs its runner ran at once |

A run passes only when every run of every phase succeeds and the state files then hold every resource the estate declares.

## What one run does

| Step | What happens |
|---|---|
| 1 Estate | choudoufu's `terralith-gen` writes a terralith, one root module of IAM roles and policies, ECS services, Route 53 records and a VPC |
| 2 Carve | the bench splits it into roots: one per team, per service, per ten DNS records and per pair of `count` or module teams, and one platform root |
| 3 Repos | the platform root and every root that reads its state go in one repo, so its waves order them; the other roots go 100 to a repo |
| 4 Control repo | its `terragucci.yml` lists every repo, and `reconcile --mode apply` opens the pipeline pull request in each one |
| 5 Create | the bench merges them all; each repo's apply waves plan every root and apply it |
| 6 Plan | a pull request in each repo changes the module whose tags every root applies |
| 7 Change | the bench merges them; the waves apply the new tags to every resource |
| 8 Verify | the state files in the bucket must hold every resource |

| 10,069 | 1,361 | 12 | 136 |

## What the numbers depend on

| Setting | In the bench | Why it matters |
|---|---|---|
| `parallelism` | 4, in each repo's `terragucci.yml` | each root a wave plans or applies starts its own AWS provider, about 800 MB |
| Jobs at once | 3 on one runner | repos run side by side only as far as the runner takes their jobs |
| Lock files | each root commits `.terraform.lock.hcl` | without one, `init` downloads the provider again for every root: on the 301-resource estate a run took 24 minutes without lock files and 8 with them |
| Emulator | the AWS emulator answers at once | a cloud account adds API latency and throttling, and IAM's default quota of 1,000 roles is below the 1,496 this estate declares |

## Running it yourself

The bench starts its own containers and calls no cloud. [CONTRIBUTING.md](https://github.com/INTENTIUS/terragucci/blob/main/CONTRIBUTING.md#the-scale-bench) says how to run it.
