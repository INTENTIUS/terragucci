## How roots are split into waves

The roots in `waves.canary` go first, then one dependency layer per wave, so no root in a wave reads another in it. The report's wave 3 is the gate `wave-3`.

In Terragrunt, the `waves.canary` units are wave 1 and the rest wave 2, ordered by the dependency graph. An approved wave applies exactly the plans its job saved.

## What an approval binds

An approval binds the wave's set digest: these exact plans are fine. It counts only when its ssh seal verifies against the signers file.

Signers and gates in [`chant.workspace.json`](/terragucci/concepts/glossary/#chantworkspacejson) come from the applied commit's first parent (the default branch before an applying pull request), so a change cannot loosen its own rule, except a multi-commit rebase: [merge or squash such changes](/terragucci/guides/approve-a-wave/#which-commit-the-rule-is-read-from).

A gated wave whose plan changed after approval applies nothing. Under `on-destroy` a re-plan with no destroy applies; under `never` nothing is refused.

## Plans are made late

Each wave plans after the last applied, on real outputs. A Terragrunt unit never plans on `mock_outputs` ([details](/terragucci/guides/use-terragrunt/#what-is-different-in-a-terragrunt-repo)).

## When a wave waits

The gate policy decides which waves wait for a person.

| Policy | Waits for an approval when |
|---|---|
| `always` | the wave has at least one change; a wave whose plans change nothing never waits |
| `on-destroy` | the wave's plans destroy or replace something |
| `never` | never; only pull request review and default branch protection stand in front of it |

A waiting wave exits with code 3 and prints the approval command; run it, then rerun the stage. A rerun resumes after the approval or failed root and never applies a root twice.

## One apply at a time

A project applies one push at a time. With `apply.when: pull-request`, an applying pull request also locks each root it reaches until it merges or closes. [Per forge](/terragucci/reference/pipeline/#one-apply-at-a-time).
