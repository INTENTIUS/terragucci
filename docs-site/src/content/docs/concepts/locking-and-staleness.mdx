With `binary: choudoufu`, the OpenTofu fork from the team behind terragucci ([set it up](/terragucci/guides/use-a-binary/#choudoufu)), a killed apply leaves no lock to release. Your repo still applies one change at a time, whatever the binary: a second push's apply waits for the first (`apply-serial`). Applies that meet outside the pipeline, such as a laptop and CI, choudoufu settles per resource.

Each row names the check that proves it: terragucci's on [Validation](/terragucci/reference/validation/), choudoufu's by claim number on its site.

## Stock and choudoufu

Stock is a state file behind a lock, as Terraform and OpenTofu keep it; choudoufu is an estate with a [record store](#record-writes).

| | Stock | choudoufu |
|---|---|---|
| A killed apply | the state lock stays held until [`terragucci unlock-state`](/terragucci/guides/release-a-state-lock/) frees it after an approval (`unlock-state`) | no lock is held, so there is nothing to release, and `force-unlock` refuses ([claim 2](https://intentius.io/choudoufu/docs/claims/no-self-managed-locks/)) |
| What a killed apply created | a resource created after the last state write is unknown to the next plan, and the re-run creates a second one ([claim 5](https://intentius.io/choudoufu/docs/claims/recovery-is-a-rerun/), its markers withheld) | a resource marked in its create call is named by the next plan and bound by the re-run, with no duplicate; [claim 42](https://intentius.io/choudoufu/docs/claims/a-killed-apply-hides-nothing/) names the types marked only after their create |
| A stale saved plan | a wave applies only plans whose digest the approval covered (`audit-refused`) | the same, and the apply re-reads the live system: if one of the plan's changes moved in address, action, live object or value, it refuses and names it ([claim 15](https://intentius.io/choudoufu/docs/claims/apply-what-was-approved/)) |
| Two applies that meet anyway, such as a laptop and CI | the second waits for the state lock (`lock-wait`) | on different resources, both land and neither waits (`cdf-concurrency`); on one record, one lands, the other fails naming it and overwrites nothing, and its re-plan shows the value that landed (`cdf-write-race`) |
| Ownership | the root's state file | a tag on each resource; a role scoped by the estate tag is refused on another estate's resources (`cdf-iam`); one bucket for every estate (`cdf-shared-bucket`) |
| Lock-wait metrics | with choudoufu as the binary, each wait is a `State lock wait` span in the report and `terragucci_lock_wait_seconds` (`lock-wait`) | none: no lock, and the report lists no waits (`cdf-concurrency`) |

A wave applies the plan file it saved, so claim 15's check runs inside the wave.

The state file is a cache: never the record of what you own, and losing it costs a refresh ([claim 5](https://intentius.io/choudoufu/docs/claims/recovery-is-a-rerun/)).

## Record writes

Each resource has its own record in the estate's record store bucket. Every record write is one conditional S3 `PutObject`, so the cloud's API settles two runs that reach one resource:

| Record write | Condition | When another run got there first |
|---|---|---|
| create | `If-None-Match: *` | the write fails, because the record exists |
| update | `If-Match: <the version it read>` | the write fails, because the version moved |

## Live resource markers

Each resource carries its identity as tags, written in its create call, or just after it for the few types whose create takes no tags.

| Tag | Holds |
|---|---|
| `tofu-estate` | the estate that owns the resource |
| `tofu-address` | the resource's address in the configuration |

| What the tags give you | How |
|---|---|
| Each address finds its real resource | the next plan matches the address to the resource that carries it in its tags |
| An estate any cloud tool can list | filter on the tag, for example `aws ec2 describe-instances --filters Name=tag:tofu-estate,Values=prod` |
| A role scoped to one estate | an IAM condition on the tag: the role applies its own estate, and IAM refuses it a change to another estate's resources |

The scoped role's write statement, for an estate called `prod`:

```json
{
  "Effect": "Allow",
  "Action": ["ec2:CreateTags", "ec2:DeleteTags", "ec2:TerminateInstances"],
  "Resource": "*",
  "Condition": { "StringEquals": { "aws:ResourceTag/tofu-estate": "prod" } }
}
```

The role also reads with `ec2:Describe*`. [choudoufu's marker spec](https://github.com/INTENTIUS/choudoufu/blob/main/live/MARKERS.md) publishes the whole grant, creates included.

## One backend for all your estates

Values the cloud has nowhere to keep go in a record store: an S3 bucket you own. One bucket serves every estate, and each root names its estate and the bucket:

```hcl
terraform {
  live {
    estate = "prod-eu"

    record_store "s3" {
      bucket = "acme-records"
    }
  }
}
```

| In the shared bucket | What you get |
|---|---|
| `tofu-records/<estate>/` | each estate's records, one per resource, under a prefix of its own |
| the `tofu-estate` tag on each object | every record carries its estate's tag |
| estates whose names start alike, such as `prod` and `prod-eu` | no shared keys: each holds only its own records, and the next plan of both shows no change |

The apply checks the bucket before it writes a record:

| Bucket setting | Value |
|---|---|
| versioning | enabled |
| lifecycle | a rule that expires noncurrent versions |
| public access blocks | all four on |

[choudoufu's bucket page](https://intentius.io/choudoufu/docs/use/bucket/) has the IAM policy for a role per estate.
