## What you end up with

A pipeline file in your repo, and a pull request with one plan note that groups the roots a change reaches and names every destroy.

To try it first, [the tutorial](/terragucci/tutorial/) runs a 15-root example on your laptop. A coding agent can do these steps: [hand it this prompt](/terragucci/getting-started/agents/).

## Before you start

| You need | Why |
|---|---|
| a repo with Terraform, OpenTofu or Terragrunt roots, on GitHub, GitLab or Forgejo | terragucci reads the roots and the forge from the repo |
| Node.js 22 or later, on your machine only | `init` is an npm package; the pipeline runs in terragucci's CI image |
| a way for CI to read your state and providers | the plan job runs `plan`; see [Environment variables and credentials](/terragucci/reference/environment/) |
| push access to the repo | you commit the generated pipeline |

## Steps

### 1. Install terragucci

From the root of the repo:

```bash
npm i -D @intentius/terragucci
```

### 2. Preview what it finds

```bash
npx terragucci init --dry-run
```

It writes nothing and prints what it found, with the reason for each choice:

```text
found 15 roots in 2 layers, tofu 1.13.1 (tofu on the path), forge github (the origin remote (github.com))
would write .github/workflows/terragucci.yml
would write chant.workspace.json
no terragucci.yml needed (defaults fit)
dry run: nothing was written
```

Roots are the directories that declare a backend or a `cloud` block, or configure a provider; [root](/terragucci/concepts/glossary/#root) covers HCP Terraform remote execution. Layers are the dependency order, and `tf-apply` builds its [waves](/terragucci/concepts/glossary/#wave) from them, canary first. If the binary or the forge is wrong, pass `--binary` or `--forge`. `--json` lists the reason for every root.

### 3. Write the pipeline

```bash
npx terragucci init
```

```text
found 15 roots in 2 layers, tofu 1.13.1 (tofu on the path), forge github (the origin remote (github.com))
wrote .github/workflows/terragucci.yml
wrote chant.workspace.json
no terragucci.yml needed (defaults fit)
```

On GitLab the file is `.gitlab-ci.yml`, and on Forgejo `.forgejo/workflows/terragucci.yml`. Every job runs in terragucci's CI image. A job downloads a tool only if you pin a version the image lacks (it runs `terragucci install` first) or set a policy (conftest is fetched on first use).

[`chant.workspace.json`](/terragucci/concepts/glossary/#chantworkspacejson) declares each wave's approval gate. Commit it: the apply job reads it from the default branch. [Your config file](/terragucci/reference/config/) lists every `terragucci.yml` key.

### 4. Give the pipeline a token

GitHub and Forgejo jobs use the run's own token. On GitLab, add a project access token with the `api` scope as a masked CI/CD variable named `GITLAB_TOKEN`.

### 5. Commit and open a pull request

```bash
git switch -c add-terragucci
git status
git add -A
git commit -m "Add terragucci"
git push -u origin add-terragucci
```

`git status` should show the pipeline file, `chant.workspace.json`, `package.json` and `package-lock.json`; add anything else, such as `node_modules`, to `.gitignore`.

Open the pull request. The check and plan jobs start on their own. If it touches no root there is nothing to plan, so change a line in one root and push again.

### 6. Read the plan note

When the plan job finishes, the pull request gets one comment and a `terragucci/plan` status. The note looks like this:

## Before your first approval

Approving a wave needs this; the plan note does not. Approvals are sealed with an ssh key, so before the first one:

1. Install [chant](/terragucci/concepts/glossary/#chant) where you approve: `npm i -D @intentius/chant`.
2. Add your public key to `.chant/allowed_signers` through a reviewed pull request to the default branch, one line per approver. [Set up the signers file](/terragucci/guides/approve-a-wave/#set-up-the-signers-file) gives the format and branch protection.

A merge counts only the keys listed before it, so merge the signers file before the first change that destroys something.
