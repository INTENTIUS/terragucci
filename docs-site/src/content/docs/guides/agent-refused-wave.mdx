import { Tabs, TabItem, Steps } from '@astrojs/starlight/components';

This is one of the three features that run a model; the others are the [`/terragucci agent` comment](/terragucci/guides/agent-change-a-pull-request/) and the [pull request review](/terragucci/guides/agent-review-a-pull-request/). It is off until you add its job by hand, and every other feature runs with no agent ([what needs an agent](/terragucci/#opt-in-coding-agent)).

## What you end up with

One comment saying what changed between the approved plan and the plan that was refused. The agent never approves, applies or merges, and its prompt forbids running [chant](/terragucci/concepts/glossary/#chant) or terragucci.

## Before you start

| You need | Why |
|---|---|
| [Fix a refused wave](/terragucci/guides/fix-a-refused-wave/) done once by hand | the agent reads the same diff you print there |
| An API key for the model | the job runs Claude Code |
| On GitHub, a forge token that can comment but not push, approve or merge | the action posts the summary as a comment; on GitLab and Forgejo the summary is in the job's log and the job needs no token |
| The refused wave's artifact, `terragucci-report-apply-wave-<k>` | it holds the approved report and the refused one |

## Steps

<Steps>

1. Produce the diff without a model. This needs no model and is the agent's input:

   ```bash
   npx terragucci respond wave-refused --approved terragucci-report/approved --current terragucci-report/current --wave 2 --json
   ```

   The envelope holds each root whose plan digest moved, with what moved inside it.

2. Add the job to a file of your own jobs, and name the file in `terragucci.yml`. `init` rewrites the pipeline file it wrote, and writes every job the file holds after its own, as the file has it, each time it runs. `reconcile` does the same in each project of a control repo.

   ```yaml
   # terragucci.yml
   own_jobs: ci/own-jobs.yml
   ```

   | What | Value |
   |---|---|
   | Runs | when a wave's apply job fails on a refusal |
   | Wave jobs | `apply-wave-<k>`; with [`waves.jobs`](/terragucci/concepts/waves-and-approvals/#a-wide-wave-across-jobs), the wave's deciding job is `apply-wave-<k>` and a refused share keeps no approved report |
   | Input | the artifact `terragucci-report-apply-wave-<k>`, holding `approved/report.json` and `current/report.json` when refused |
   | Wave in the examples | 2; change the number everywhere for another |
   | Claude Code | pinned to 2.1.290, the release the [agent comment](/terragucci/guides/agent-change-a-pull-request/) job runs |

   <Tabs syncKey="forge">
     <TabItem label="GitHub">
       `ci/own-jobs.yml`. The job runs in the `terragucci` workflow after the wave's job, and reads that run's artifact.

       ```yaml
       explain-refusal:
         needs: apply-wave-2
         if: failure()
         runs-on: ubuntu-latest
         permissions:
           contents: read
           pull-requests: write
           issues: write
         steps:
           - uses: actions/checkout@v4
           - uses: actions/download-artifact@v4
             continue-on-error: true
             with: { name: terragucci-report-apply-wave-2, path: reports }
           - run: >
               test -d reports/approved || exit 0;
               npx -y @intentius/terragucci respond wave-refused
               --approved reports/approved --current reports/current --wave 2
               --json > refusal.json
           - if: hashFiles('refusal.json') != ''
             uses: anthropics/claude-code-action@v1
             with:
               anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
               github_token: ${{ secrets.AGENT_FORGE_TOKEN }}
               prompt: |
                 Read refusal.json. Summarize which roots changed since the approval and why
                 the plan moved, in five lines or fewer. Do not run chant approve,
                 terragucci or any apply command.
       ```
     </TabItem>
     <TabItem label="GitLab">
       `ci/own-jobs.yml`. `init` writes the job into `.gitlab/terragucci.yml`, which your `.gitlab-ci.yml` includes. It runs after the wave's job, and the artifact unpacks at `terragucci-report/`. Its rule is the apply jobs' own, so a branch's pipeline, which has no `apply-wave-2`, does not need it. Give it `ANTHROPIC_API_KEY` as a masked variable. The job posts nothing: read the summary in its log.

       ```yaml
       explain-refusal:
         stage: apply
         needs: [apply-wave-2]
         rules:
           - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH && $CI_PIPELINE_SOURCE != "schedule"
             when: on_failure
         image: node:24
         script:
           - >
             npx -y @intentius/terragucci respond wave-refused
             --approved terragucci-report/approved --current terragucci-report/current --wave 2
             --json > refusal.json
           - >
             npx -y @anthropic-ai/claude-code@2.1.290 -p
             "Read refusal.json. Summarize which roots changed since the approval and why
             the plan moved, in five lines or fewer. Do not run chant approve,
             terragucci or any apply command."
       ```
     </TabItem>
     <TabItem label="Forgejo">
       `ci/own-jobs.yml`. Forgejo's runner takes `actions/download-artifact@v3`, which reads only its own run's artifacts, so the job runs in the `terragucci` workflow beside the wave's job. `anthropics/claude-code-action` is a GitHub app, so run the CLI in the job and read the summary in its log. The key is a repository secret; the job needs no write token.

       ```yaml
       explain-refusal:
         needs: apply-wave-2
         if: failure()
         runs-on: docker
         container: node:24
         steps:
           - uses: actions/checkout@v4
           - uses: actions/download-artifact@v3
             with: { name: terragucci-report-apply-wave-2, path: reports }
           - run: >
               test -d reports/approved || exit 0;
               npx -y @intentius/terragucci respond wave-refused
               --approved reports/approved --current reports/current --wave 2
               --json > refusal.json
           - run: >
               test -f refusal.json || exit 0;
               npx -y @anthropic-ai/claude-code@2.1.290 -p
               "Read refusal.json. Summarize which roots changed since the approval and why
               the plan moved, in five lines or fewer. Do not run chant approve,
               terragucci or any apply command."
             env:
               ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
       ```
     </TabItem>
   </Tabs>

   Then run `npx terragucci init` and commit the pipeline with the file. A job name `init` already gives one of its own jobs is refused.

3. Read the summary, then decide. Choose between approving the new plan and reverting the change. The choice and the approval ([`terragucci approve`](/terragucci/reference/cli/#approve)) are yours.

</Steps>
