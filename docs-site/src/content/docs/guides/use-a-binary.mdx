## What each binary gives the pipeline

Every binary runs the same four stages: `tf-check`, `tf-plan`, `tf-apply` and `tf-drift`. choudoufu, the OpenTofu fork from the team behind terragucci, adds the most: [nine features](#choudoufu) on top of OpenTofu's.

| | choudoufu | Terraform | OpenTofu | Terragrunt |
|---|---|---|---|---|
| State | no state file: one record per resource in an S3 backend, and a tag on each resource | your backend | your backend | each unit's backend |
| What `tf-check` runs | `fmt -check`, `validate`, [`live-check`](/terragucci/reference/stages/#check) | `fmt -check`, `validate` | `fmt -check`, `validate` | `hcl fmt --check`, `hcl validate` |
| What the report times | each resource; [slow provider calls](/terragucci/reference/observability/#what-the-report-lists), [summed timings](/terragucci/reference/observability/#what-the-report-lists) on a large estate and [lock waits](/terragucci/reference/observability/#state-lock-waits) on a locking backend | per-resource timings: not reported (Terraform sends no traces) | each resource | each unit, from Terragrunt's run report |
| CI image | `terragucci-choudoufu`, choudoufu 0.23.0 | `terragucci-terraform`, Terraform 1.14.9 | `terragucci-tofu`, OpenTofu 1.13.1 | `terragucci-terragrunt`, Terragrunt 1.1.6 and OpenTofu 1.13.1 |
| Version pin | `version` only | `version`, `.terraform-version`, or an exact `required_version`; per root too | `version`, `.opentofu-version`, or an exact `required_version`; per root too | `terragrunt.version`, or an exact `terragrunt_version_constraint`; per unit too, with the binary's pins |

A pin the image does not carry is installed in the job, checked against the release's SHA256SUMS. Images are pinned by digest.

### A version per root

A root with its own `.opentofu-version` or `.terraform-version`, or an exact `required_version`, runs that version, and the rest of its wave runs the job's. `version` in `terragucci.yml` can also be a map of root glob to version:

```yaml
binary: tofu
version:
  "envs/legacy/*": "1.9.1"
```

The plan job installs each pinned version once and plans each root with its own; the apply job does the same. The plan note and the report name each root's binary and version:

```text
Binaries: tofu 1.10.6 for `old` (.opentofu-version); tofu 1.13.1 for 1 root.
```

Run `npx terragucci init` after adding a pin, so the check job validates each root with its version too. [A version per root](/terragucci/reference/config/#a-version-per-root) has the order the pins are read in.

<TabItem label="choudoufu">

```yaml
binary: choudoufu
```

[choudoufu](https://github.com/INTENTIUS/choudoufu) is the OpenTofu fork from the team behind terragucci, and `binary: choudoufu` runs the same four stages on it. Nine things come with it:

| You get | Where you see it |
|---|---|
| A live check in `tf-check` on every push, before the apply waves, with no cloud credentials | [the `tf-check` log and check report](/terragucci/reference/stages/#check) |
| No state file, and locks that settle at the API: one record per resource in an S3 backend, each write conditional, so there is no lock table or database to run | [Locking per resource](/terragucci/concepts/locking-per-resource/#locking-per-resource) |
| Each address finds its real resource: the apply writes a tag on each resource and the next plan reads it back | [Live resource markers](/terragucci/concepts/locking-per-resource/#live-resource-markers) |
| How long a wave waited for a state lock, and how many tries it took, on a backend that locks | [the report, the trace and a metric](/terragucci/reference/observability/#state-lock-waits) |
| Which provider calls were slow, and the resource each was for | [the report's provider calls](/terragucci/reference/observability/#what-the-report-lists) |
| Reports that stay readable past a span budget on a large estate, with timings summed by resource type | [the report's summed timings](/terragucci/reference/observability/#what-the-report-lists) |
| Two applies that change different resources of one estate run at once, with no estate-wide lock; two that change the same resource leave one winner and a write conflict naming it | [your applies](/terragucci/concepts/locking-per-resource/#locking-per-resource); the loser's re-plan shows the value that landed |
| A role scoped to one estate by its ownership tag: it applies that estate and is refused on another estate's resources | [your cloud's IAM](/terragucci/concepts/locking-per-resource/#live-resource-markers) |
| One record store bucket for every estate, each under its own prefix | [your bucket](/terragucci/concepts/locking-per-resource/#one-backend-for-all-your-estates) |

`init` never picks choudoufu on its own: set `binary: choudoufu` or run `npx terragucci init --binary choudoufu`.

A `live-check` refusal fails `tf-check` and names its rule in the log. terragucci does not read a root's `required_version` as a choudoufu release.
</TabItem>

`init` picks it for a `.opentofu-version` file or `.tofu` files, and when nothing points elsewhere.

</TabItem>
<TabItem label="Terragrunt">

```yaml
binary: tofu   # or terraform: the tool Terragrunt calls
```

A `root.hcl` or `terragrunt.hcl` turns on Terragrunt, and each unit is a root. Under Terragrunt, `binary` is `tofu`, `terraform` or `choudoufu`, which Terragrunt calls through `TG_TF_PATH`. Terraform is installed in the job; with `choudoufu` the jobs run in the choudoufu image and install Terragrunt. See [Use Terragrunt](/terragucci/guides/use-terragrunt/).

</TabItem>

## Steps

<Steps>

1. See what `init` picked. The first line names the binary and why.

   ```bash
   npx terragucci init --dry-run
   ```

   ```text
   found 15 roots in 2 layers, tofu 1.13.1 (tofu on the path), forge github (the origin remote (github.com))
   ```

   `binary:` in `terragucci.yml` comes first, then `--binary`, then:

   | Order | Source | Binary |
   |---|---|---|
   | 1 | `.opentofu-version` | `tofu` |
   | 2 | `.terraform-version` | `terraform` |
   | 3 | `.tofu` files in a root | `tofu` |
   | 4 | `tofu` on the path | `tofu` |
   | 5 | `terraform` on the path | `terraform` |
   | 6 | nothing found | `tofu` |

   If it picked the one you want, stop here.

2. Put your tab's `binary:` line in `terragucci.yml`, or run `npx terragucci init --binary <name>`.

3. Write the pipeline again and commit it.

   ```bash
   npx terragucci init
   ```

   ```text
   found 15 roots in 2 layers, tofu 1.13.1 (terragucci.yml), forge github (the origin remote (github.com))
   updated .github/workflows/terragucci.yml
   using terragucci.yml
   ```

</Steps>
