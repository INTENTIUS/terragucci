## Result

The repo's pipeline runs the new release, moved by a pull request you reviewed, like any other version.

## Steps

<Steps>

1. Install the new release where the repo pins it:

   ```bash
   npm i -D @intentius/terragucci@<version>
   ```

2. Check the config against it and write the pipeline again:

   ```bash
   npx terragucci config check
   npx terragucci init
   ```

   `init` writes the pipeline with the new release's image, by tag and digest. [Changes in each release](/terragucci/reference/whats-new/) lists what moved.

3. Open a pull request with `package.json`, `package-lock.json` and the files `init` wrote. The pipeline's diff shows the image moving and anything else the release changed in the jobs.

4. Merge it. The jobs run the new release from the next push. Approvers update the terragucci they run `terragucci approve` with the same way.

</Steps>

With [`image`](/terragucci/reference/config/#keys) set, the jobs run your own image, built `FROM` terragucci's: rebuild it from the new release's image and name it in `image` before step 2.

In a [control repo](/terragucci/concepts/control-repo/), upgrade the control repo's own install and run `terragucci reconcile --mode apply`: each project gets a pull request with its new pipeline.
