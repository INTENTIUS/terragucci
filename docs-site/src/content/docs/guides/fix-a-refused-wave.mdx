## What you end up with

A decision on a refused wave: either the new plan approved and applied, or the change that moved it removed.

## Before you start

- A wave that stopped with a refusal: the job says the set digest no longer matches its approval, and nothing in the wave applied.
- The apply job's log. Unless `respond.wave-refused` is `off`, it prints the diff from step 3.

## Steps

<Steps>

1. Understand why it refused.

   An approval binds a wave's set digest, so any root's plan changing after it means the wave applies nothing. The usual cause is another merge touching a root in the wave, or a data source reading a new value.

   In the example, approve the waiting wave, then merge the module bump. Its job stops and names the roots that moved:

   <Shot step="wave-refused" view="log" alt="The apply job's log after a module bump: the wave applies nothing, exit code 4, both digests and the roots whose plans moved" optional />
   <Captured step="wave-refused" cmd="just example merge" optional />

2. Get the two reports.

   The approved report is on [`chant/lifecycle`](/terragucci/concepts/glossary/#chantlifecycle) at `_gates/tf-apply/wave-<k>/<digest>.json` (`:` written as `_`). The refused job writes it to `terragucci-report/approved/report.json` and its own to `terragucci-report/current/report.json`. To fetch the approved one locally:

   ```bash
   git fetch origin chant/lifecycle
   mkdir -p approved
   git show origin/chant/lifecycle:_gates/tf-apply/wave-2/jcs1-sha256_<hex>.json > approved/report.json
   ```

   The current report stays in the job's workspace, so the job's log is the easiest place to read step 3.

3. Print the diff.

   ```bash
   npx terragucci respond wave-refused --approved approved --current terragucci-report/current --wave 2
   ```

   It lists each root whose plan digest moved, with what changed inside it. `--json` prints one envelope.

4. Decide.

   | Choice | Command | Result |
   |---|---|---|
   | Keep the new plan | `npx chant approve tf-apply wave-2 --plan <new digest>` (add `--sign` under `approval: sealed`), then run the stage again ([Approve a waiting wave](/terragucci/guides/approve-a-wave/)) | The new plans apply. |
   | Drop it | Revert the change on the default branch. | The old approval does not come back: the refused run recorded a newer pending fact, so the wave waits for a fresh `chant approve`. |

</Steps>

An agent may [summarize the diff](/terragucci/guides/agent-refused-wave/), but it does not re-approve.
