The [estate page](/terragucci/guides/see-every-project/) counts per project. [behold](https://intentius.io/behold/using/terragucci/) draws one repo's roots and resources as a graph and marks each resource with what your runs last found about it. It runs on your machine against the checkout and the reports bucket. Nothing is written, and the pipeline never needs it.

## Result

```bash
npx --yes -p @intentius/behold@0.30.0 -p @intentius/chant-lexicon-terraform@^0.124.0 -p @cdktn/hcl2json@^0.24.0 \
  behold serve . --terragucci s3://acme-terragucci/reports
```

Use the bucket and prefix from your `terragucci.yml`, then open `http://127.0.0.1:4600`. Each root is a box of its resources. A resource a run flagged carries a mark with the time that run finished, and the **Terragucci** tab lists every root with its newest drift check, plan and apply wave.

## Marks

| Mark | Means | From |
|---|---|---|
| ⚠ drift | the newest drift check found the resource changed or deleted outside Terraform, or existing outside the state | the root's newest `tf-drift` report |
| ~ plan | the newest plan that holds the root would change the resource, with its pull request | the root's newest `tf-plan` report |
| ⏸ wave | a wave waiting for an approval would change the resource | the waiting `tf-apply` wave's report |

Each card's corner says how old its newest mark is. Click a card to list its marks with the finish time and report of each run. A mark is what a run saw when it ran, and nothing on the page is a live read. A card with no mark is one no report names; it may still differ from the cloud. A root no run planned says "no report".

When the bucket holds `estate.json`, behold shows the estate page's own counts.

## Waiting waves

A waiting wave lists its roots and what it destroys or replaces. It says how long it has waited and gives the line to approve it:

```bash
npx terragucci approve wave-2 --plan jcs1-sha256:2e0f...
```

behold has no approve button. Run the line in your shell, which records the approval on [`chant/lifecycle`](/terragucci/concepts/glossary/#chantlifecycle) against that plan digest, as in [Approve a wave](/terragucci/guides/approve-a-wave/). In a repo with a `terragucci.yml`, behold refuses to deploy or approve or start a run.

## Prerequisites

| You need | Why |
|---|---|
| Node.js 20 or later | `npx` runs terragucci and behold |
| a checkout of the repo | behold draws the roots from its Terraform files |
| [reports in a bucket](/terragucci/guides/keep-reports-in-a-bucket/) | the marks come from the reports there |
| read access to the bucket, or a copy of the prefix | behold reads the reports with your own credentials |

## Steps

<Steps>

1. Give your shell read access to the reports. behold reads an S3 prefix with your AWS profile. A read-only identity needs `s3:GetObject` on these keys:

   ```text
   <prefix>/*index.json
   <prefix>/*/report.json
   <prefix>/estate.json
   <prefix>/audit.jsonl
   <prefix>/*/runs/*/run.json
   ```

   `audit.jsonl` fills the timeline. Each `run.json` fills a project's apply progress and run view.

   Without `s3:ListBucket` S3 answers 403 for a missing key. A project that never applied has no `run.json`, so that part shows as not readable.

   For a GCS or Azure bucket, set `reports.url`, or copy the prefix to a directory with `gcloud storage rsync` or `azcopy`.

2. From the repo's root, run the command under [Result](#result). To read a copy instead of the bucket, pass the directory:

   ```bash
   aws s3 sync s3://acme-terragucci/reports ./reports
   npx --yes -p @intentius/behold@0.30.0 -p @intentius/chant-lexicon-terraform@^0.124.0 -p @cdktn/hcl2json@^0.24.0 \
     behold serve . --terragucci ./reports
   ```

3. If the bucket holds several repos and none matches this checkout's git remote, add `--terragucci-project github.com/acme/infra`.

4. Stop it with Ctrl-C. behold binds `127.0.0.1` only.

</Steps>

## Roots by wave

`terragucci init` writes [`terragucci.components.json`](/terragucci/reference/cli/#the-components-file) at the repo's root. It lists each root with the roots it follows, each wave's roots, and the pipeline's job that applies them, in the pipeline's own job names. For the four roots of a repo where `app` reads `network`'s state, `edge` reads `app`'s and `other` reads nothing, the jobs are:

```json
[
  { "name": "apply-wave-1", "needs": ["check"], "wave": 1, "applies": ["network", "other"] },
  { "name": "apply-wave-2", "needs": ["apply-wave-1"], "wave": 2, "applies": ["app"] },
  { "name": "apply-wave-3", "needs": ["apply-wave-2"], "wave": 3, "applies": ["edge"] }
]
```

Commit it with the pipeline. behold 0.30.0 reads it and draws the roots grouped by wave, each wave titled with the job that applies it.

## Limits

- behold 0.30.0 reads repos whose [`chant.workspace.json`](/terragucci/concepts/glossary/#chantworkspacejson) asks for `minReader` 0.124.46 or older; `terragucci init` writes 0.102.0. It refuses a repo that asks for a newer reader.
- A malformed `index.json`, `report.json` or `estate.json` is refused with what to fix, rather than drawn.
- A [control repo](/terragucci/concepts/control-repo/) has no roots of its own, so behold draws nothing there. Serve each project's repo.

## Share a view

For a link the team can open without running anything, the estate job can publish a static view next to the estate page: see [A resource graph beside the page](/terragucci/guides/see-every-project/#a-resource-graph-beside-the-page). behold is never hosted as a shared server.
