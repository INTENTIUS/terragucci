## What you end up with

A message in your channel each time an apply job stops at a wave. A message approves nothing. A person approves with `terragucci approve` from a checkout, which records the approval on [`chant/lifecycle`](/terragucci/concepts/glossary/#chantlifecycle), or, under `approval: pr-review`, by approving the pull request on the forge.

| The wave | Exit | The message says |
|---|---|---|
| waits for an approval | 3 | the wave, its roots, its plan digest, the [`chant approve`](/terragucci/concepts/glossary/#chant) command for that digest, and the run; under `approval: pr-review`, first a link to review the pull request ([below](#approve-from-the-message-by-review)) |
| is refused: its plans changed after approval | 4 | the wave, its roots, the outcome line, `npx terragucci approve wave-<k>` for the new digest, and the run |
| fails, or the policy denies it | 1 | the wave, its roots, the outcome line, that there is nothing to approve, and the run |

## Before you start

| You need | Why |
|---|---|
| The [pipeline](/terragucci/getting-started/) | `init` maps the secret into the apply jobs |
| An incoming webhook for the channel | the apply job posts to it |
| A secret in your forge's store holding the webhook's address | the address is a credential: anyone holding it can post |

## Steps

<Steps>

1. Make a webhook for the channel.

   <Tabs syncKey="chat">
     <TabItem label="Slack">
       In a Slack app with Incoming Webhooks turned on, add a webhook to the channel. Copy its `https://hooks.slack.com/services/...` address.
     </TabItem>
     <TabItem label="Teams">
       In the channel, add the Workflows template "Post to a channel when a webhook request is received", and copy the address it gives. terragucci posts an Adaptive Card, the body that template reads.
     </TabItem>
   </Tabs>

2. Store the address as a secret.

   <Tabs syncKey="forge">
     <TabItem label="GitHub">
       A repository secret under Settings, Secrets and variables, Actions.
     </TabItem>
     <TabItem label="GitLab">
       A masked CI/CD variable. Mark it Protected so only default-branch pipelines, where the apply jobs run, see it.
     </TabItem>
     <TabItem label="Forgejo">
       The same as GitHub; Forgejo keeps them under Settings, Actions, Secrets.
     </TabItem>
   </Tabs>

3. Name the secret in `terragucci.yml`. Use either key, or both:

   ```yaml
   notify:
     slack: SLACK_WEBHOOK_URL
     teams: TEAMS_WEBHOOK_URL
   ```

   The value is the secret's name. `config check` refuses an address.

4. Write the pipeline again and merge it.

   ```bash
   npx terragucci init
   ```

   Each apply job gets the secret as `TERRAGUCCI_SLACK_WEBHOOK` or `TERRAGUCCI_TEAMS_WEBHOOK`, and runs `terragucci notify` when its wave stops. No plan job gets it.

5. Read the next message.

   <Tabs syncKey="chat">
     <TabItem label="Slack">
   ```text
   terragucci: wave 2 of github.com/acme/infra waits for an approval
   Roots: envs/prod/app, envs/prod/db
   Approve: chant approve tf-apply wave-2 --plan jcs1-sha256:9f2c... (or npx terragucci approve wave-2)
   Run: https://github.com/acme/infra/actions/runs/42
   ```
     </TabItem>
     <TabItem label="Teams">
       An Adaptive Card titled with the same first line. Its facts are Wave, Roots, Approve and Run, and its one button opens the run.
     </TabItem>
   </Tabs>

</Steps>

| If the webhook | The job |
|---|---|
| answers 2xx | logs `terragucci notify: posted to Slack` (or Teams) |
| answers an error, or not within 10 seconds | logs the status and goes on; the wave's own exit code stands |

A comment that applies (`/terragucci apply`) posts the same messages from its job.

## Approve from the message, by review

With [`approval: pr-review`](/terragucci/guides/approve-a-wave/#approve-by-review-approval-pr-review), a waiting wave's message opens with a link to the pull request's review page, when an approving review of its head would approve the wave. The approval stays a person's own review on the forge, bound to the plans the pull request's note recorded; the chat app holds no key and approves nothing.

```text
terragucci: wave 2 of github.com/acme/infra waits for an approval
Review and approve: pull request 12, then run the wave again
Roots: envs/prod/app, envs/prod/db
Digest: jcs1-sha256:9f2c...
Or approve: chant approve tf-apply wave-2 --plan jcs1-sha256:9f2c... (or npx terragucci approve wave-2)
Run: https://github.com/acme/infra/actions/runs/42
```

In Teams the card's first button, Review and approve, opens the same page.

| Forge | The link opens | Given when |
|---|---|---|
| GitHub | the pull request's Files changed tab, where Review changes > Approve is | the wave's pull request has no approving review of its head, or a reviewer asked for changes, and its plan note has a digest for the wave |
| Forgejo | the pull request's Files changed tab, where Review > Approve is | the same |
| GitLab | the merge request, where Approve is | the same, and the merge request is still open (applied before it merges): GitLab takes no approval of a merged one |

No link is given for a direct push, a wave the pull request's note has no digest for, or a refused wave: no review of that head can approve those plans. The message then offers the approve command alone.

After the review, run the wave again: comment `/terragucci apply` on the pull request, or re-run the job ([Run the stage again](/terragucci/guides/approve-a-wave/#approve-with-chant)). The wave finds the approving review of the head, records it on `chant/lifecycle` with `via: pr-review`, and applies.
