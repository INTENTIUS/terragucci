One of the features that run a model ([what needs an agent](/terragucci/#opt-in-coding-agent)), off unless `agent.drift` is set.

## Result

When a [drift run](/terragucci/guides/turn-on-drift-checks/) opens the drift issue, a coding agent reads what drifted and changes the code to describe what is live. terragucci opens a pull request with the change and links it on the issue:

```text
terragucci: the drift agent opened https://forgejo.example/acme/infra/pulls/2, changing `app/main.tf`.
It plans like any other pull request; nothing was applied, approved or merged.
```

Merging the pull request keeps the change made outside the code, and its apply goes through the gate. Closing it and applying the code as it is undoes the drift instead.

## Prerequisites

| You need | Why |
|---|---|
| [Drift checks](/terragucci/guides/turn-on-drift-checks/) on GitHub or Forgejo | the agent runs when the drift job opens the drift issue; `init` refuses `agent.drift` on GitLab |
| An Anthropic API key in your forge's secrets | the default command runs Claude Code |
| A token for the pull request in your forge's secrets (step 1) | a pull request opened with the job's own token starts no workflow run, so it would not be planned |

## Steps

<Steps>

1. Make the agent's token. Keep it in a secret such as `AGENT_FORGE_TOKEN`, and the model's key in `ANTHROPIC_API_KEY`. It is the same token, with the same settings, as the [agent comment's](/terragucci/guides/agent-change-a-pull-request/).

   <Tabs syncKey="forge">
   <TabItem label="GitHub">

   | Setting | Value |
   |---|---|
   | Who | a machine user with write access, outside `CODEOWNERS` |
   | Token | fine-grained, for this repository alone |
   | Contents, pull requests, issues | read and write |
   | Workflows | none, so GitHub refuses any change it sends to `.github/workflows/` |
   | Default branch ruleset | a pull request and one approval of the latest change required, with no bypass for the machine user |

   </TabItem>
   <TabItem label="GitLab">
   `init` refuses `agent.drift` on GitLab.
   </TabItem>
   <TabItem label="Forgejo">

   | Setting | Value |
   |---|---|
   | Who | a machine user added as a collaborator with Write access |
   | Token scopes | `write:repository` and `write:issue` |
   | Default branch | the machine user stays off the push, approval and merge allowlists |

   </TabItem>
   </Tabs>

2. Turn it on in `terragucci.yml`. The agent's pull request replaces the codified one, so set `respond.drift` to `off` (or `attribute`, to keep who changed what in the issue):

   ```yaml
   drift: "17 4 * * *"
   respond:
     drift: off
   agent:
     via: forge
     token_env: AGENT_FORGE_TOKEN
     drift:
       key_secret: ANTHROPIC_API_KEY
       max_turns: 30
       timeout: 30
   ```

   `drift: true` under `agent` takes every default; the keys are the [agent comment's](/terragucci/reference/config/#the-drift-agent).

3. Check the file and write the pipeline, then merge the result to the default branch:

   ```bash
   npx terragucci config check
   npx terragucci init
   ```

4. Wait for drift, or run the drift workflow by hand. The drift issue gets the pull request's link; read the pull request and its plan note before you merge or close it.

   The pull request's author is the user the agent's token acts as, so its review never counts. When you run the drift workflow by hand, the agent's commit carries a `Requested-by:` trailer with your login, and your review of the pull request doesn't count either. A pull request a scheduled run opened has nobody behind it, and any other writer's review counts ([Eligible approvers](/terragucci/guides/approve-a-wave/#eligible-approvers)).

</Steps>

## The jobs

The drift job is a [chant](/terragucci/concepts/glossary/#chant) drift Op ([Turn on drift checks](/terragucci/guides/turn-on-drift-checks/)), and `agent.drift` adds chant's agent job and push job after it:

| File | Holds |
|---|---|
| `.chant/ops/terragucci-drift.sh` | the drift step's script, the same `terragucci stage tf-drift` run, so the drift report, the drift issue, `respond.drift` and `notify` are unchanged |
| `.chant/ops/terragucci-drift.spec.json` | one scheduled Op on `drift`'s cron that runs the script, keeps the drift report as an artifact, and holds chant's drift agent from `agent.drift` |
| `.github/workflows/terragucci-drift.yml` (or `.forgejo/workflows/`) | chant's drift job, then its agent job and push job |
| `ops/terragucci-drift.op.ts` | a `TerraformWatchOp` per root of a plain repo, so `chant run terragucci-drift-<root>` reads one root by hand |

One job plans every root, since the repo keeps one drift issue. A run that opens the drift issue exits with chant's `drift` code (2), so the run shows red and chant's agent job runs with the run's output in its prompt. The prompt treats that output and every file as untrusted input, since a value in the cloud can hold any text. The keys map as they do for [the comment agent](/terragucci/guides/agent-change-a-pull-request/#on-chants-agent-job), and the runs are recorded under op `terragucci-drift`.

## Permissions

| Job | Does | Holds |
|---|---|---|
| the drift job | plans every root with `-refresh-only`, opens the drift issue, and exits with the `drift` code when it did | the plan role, and its token for the issue |
| the agent job | runs the agent on the commit the drift job planned, and keeps its change as a patch | a read-only job token, which the agent's step runs without; the model's key, in the agent's step alone |
| the push job | applies the patch in a fresh job, refuses one that touches a [guarded path](/terragucci/reference/pipeline/#paths-an-agent-cannot-change), and opens or updates the pull request from `terragucci/agent/terragucci-drift`, while every commit on that branch is the agent's | the agent's token |
| the plan job | plans the pull request with its read-only role | the plan role |

Neither agent job has a cloud role, whatever `oidc` says. Nothing here applies, approves or merges. `agent.drift` runs on GitHub and Forgejo.

## Other agents

`command` takes any command line that reads a prompt on stdin and edits files in the working directory; `TG_AGENT_PROMPT` holds the prompt's path and `TG_AGENT_MAX_TURNS` the turn limit, as for the [agent comment](/terragucci/guides/agent-change-a-pull-request/#use-another-agent).

```yaml
agent:
  via: forge
  token_env: AGENT_FORGE_TOKEN
  drift:
    command: my-agent --non-interactive
    key_secret: MY_AGENT_KEY
```

## Read drift over MCP or `--json`

An agent at your desk reads the same drift without a model in the pipeline: `terragucci mcp`'s `index` tool lists the `tf-drift` runs and `report` reads one ([Read the estate over MCP](/terragucci/guides/agent-read-over-mcp/)). To change the code or the config, it runs the CLI with `--json`.
