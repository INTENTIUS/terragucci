## The lifecycle around your roots

Welcome, Terraform and Terragrunt users. terragucci carries a root through review, rollout and the watch that follows, and you write none of the pipeline.

<Lifecycle />

## One note for two hundred plans

A change to a shared module can touch hundreds of roots. Your reviewer gets one note on the pull request that groups the roots taking the same change. Every destroy and every replacement is still named.

<PlanNote />

The note links to the full report. It opens on the destroys and the outliers with the identical groups folded away, and every root in it links to its full plan. Scripts read the same data as JSON. [The plan report](/terragucci/reference/report/) shows both.

## Rollouts in waves

The change goes out a few roots at a time. Each wave waits for its own approval, and that approval covers exactly the plans it was given.

<Waves />

Each wave's state and set digest are in the report, linked to the approval record that let it go out. A pinned module rolls out the same way, one pull request per wave, across as many repos as use it.

## Or let your agent do it

Paste one prompt into Claude Code, Codex or Cursor, and your agent reads the docs from [`llms.txt`](https://intentius.io/terragucci/llms.txt), writes the config and opens a pull request. It never applies and never approves. [The prompt](/terragucci/getting-started/agents/) is on the agents page.

## Start with one file

Most repos need no config at all. Install terragucci and let it read the repo:

```bash
npm i -D @intentius/terragucci
npx terragucci init
```

It writes the pipeline for your forge. For many repos at once, one `terragucci.yml` in a control repo opens a pull request in each.

[Write your config file](/terragucci/getting-started/config/)
