## The lifecycle around your roots

[chant](/terragucci/concepts/glossary/#chant) stages, rendered for your forge, run the whole lifecycle of a root, and you write no pipeline. [How terragucci works](/terragucci/concepts/how-it-works/).

<Lifecycle />

## One note for two hundred plans

One pull request note groups roots taking the same change and names every destroy and replacement.

<PlanNote />

[The full report](/terragucci/reference/report/) opens on destroys and outliers, links every root's plan, and comes as JSON too.

## Rollouts in waves

The change goes out a few roots at a time, the [canary](/terragucci/concepts/glossary/#canary) roots first. By default a wave that destroys or replaces something waits for an approval, and that approval covers exactly the plans it was given.

<Waves />

The report lists each wave with its [set digest](/terragucci/concepts/glossary/#set-digest) and links the approval record that let it go out.

A pinned module rolls out the same way: one pull request per wave, across as many repos as use it.

## Hand the setup to your agent

Paste this into Claude Code, Codex or Cursor in your Terraform repository. [The agent page](/terragucci/getting-started/agents/) says what the agent does. It never applies and never approves.

<Landing part="agent" />

When it has run, the [guides](/terragucci/guides/add-to-github/) and the [reference](/terragucci/reference/config/) cover tasks and details. The [concepts](/terragucci/concepts/how-it-works/) and the [glossary](/terragucci/concepts/glossary/) explain the reasons and the words.
